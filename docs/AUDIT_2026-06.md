# Codebase Audit — 2026-06

Ten parallel agents audited ten independent slices of the codebase, each grounded in a fresh read of the actual files (not docs, not memory). This is the consolidated result.

**Every finding was re-verified against the source before any action.** Findings are sorted into three buckets:

- **FIXED** — concrete, verified, low-risk; fixed in this PR.
- **FLAGGED** — real, but in a protected/sensitive path (auth secrets, crypto, billing) or with rollout/regression risk, or already in flight in another PR. Needs a decision before editing. Recommendation given.
- **DOCUMENTED** — defense-in-depth, TOCTOU, or hardening backlog. Real hygiene, low exploitability or larger change; not churned now.

The global root cause behind most isolation findings: **Supabase service-role key bypasses RLS**, so every tenant boundary is one `.eq('spaceId', …)` in app code with no DB backstop. See `SEAMS` notes in `SYSTEMS.md`.

## FIXED — round 2 (flagged items, approved & resolved)

Verified: `pnpm typecheck` clean.

- **Secrets fail-closed** — `lib/crypto.ts` and `lib/client-auth.ts` no longer degrade to `sha256("")` / a hardcoded dev string; they throw if no secret is set. The `CLERK_SECRET_KEY` fallback is kept **deliberately** so existing encrypted data and live client sessions don't break — moving to a dedicated key is a separate re-encryption/rotation task.
- **Client-portal isolation** — `clientOwnsContact` + portal data now escape LIKE metacharacters (`%`/`_`), so a `%@gmail.com` registration can't match other contacts; `issueCode` invalidates prior unconsumed OTP codes on reissue.
- **Stripe webhook** — dedup TTL 24h→72h (covers the retry window); `invoice.payment_succeeded` now verifies the subscription's customer owns the Space before crediting it active.
- **GCal token encryption** — `tours/available` now decrypts on read and encrypts on write, matching `lib/gcal-helpers.ts`.

## FIXED — round 3 (hardening backlog, the 4 prioritized classes)

## FLAGGED — remaining (deliberately not auto-fixed)

Each below is real but either needs a schema migration, touches a protected runtime I won't blind-edit, or is an intentional product decision. Recommendation given for each.

- **TOCTOU needing DB constraints** (checklist seed double-insert, pipeline bootstrap duplication, brokerage seat-cap double-spend): the correct fix is a unique/partial index — a schema **migration**. Not adding migrations to the protected schema unilaterally. Rec: add the unique indexes + `ON CONFLICT DO NOTHING`.
- **Studio spend-cap TOCTOU**: app-level fix is a Redis `INCR` gate, but it rewrites a **money** path; rec it, don't blind-change it.
- **Agent run-lock GET+DEL** (`agent/security/budget.py`): already safe by construction — the lock TTL (660s) exceeds Modal's 600s hard-kill, so a run releases before its lock can be re-claimed (the code says so). A Lua CAS is nicer but unnecessary and needs a Modal redeploy. Low priority.
- **Duplicate `permission_required` emission** + **`'maybe'` approval gate** (`sdk-chat-stream`, `sdk-bridge`): touch Chippi's streaming/approval core; the auditors were themselves uncertain. Needs a dedicated, runtime-tested change — blind edits here break approvals.
- **`merge-persons` cross-space DealContact**: requires a contact id shared across spaces, which the in-space lookups make impossible. Not exploitable.
- **Packet null `expiresAt` = permanent link**: the create route defaults to 7 days; `null` is only reachable when the client explicitly opts in, and the code marks that intentional. Product decision, not a bug.
- **Telnyx webhook auth/idempotency**: already in flight in **PR #278**.

## DOCUMENTED — hardening backlog (by system)

Real but low-exploitability or larger-change items. Good hygiene; not churned in this PR.

**Auth/Trust:** GET `/api/*` bypasses the DB ban check until Clerk metadata propagates (add `platformRole==='banned'` to `requireAuth`); ban redirect returns 307 to a login page for API calls instead of 403 JSON; `requirePlatformAdmin` blind spot now fixed, but `app/admin/layout.tsx` has no try/catch around `requireAdmin()`.

**CRM (defense-in-depth `spaceId` scoping):** `deals/[id]/activity:36`, `contacts/[id]/timeline:40` (Tour), `contacts/[id]/rescore:47,107`, `deals/[id]/contacts/[contactId]:52` (DealContact PATCH), `deals/route` + `stages/route` Contact embeds. Parent rows already enforce the boundary; add child scoping as a backstop. Also TOCTOU: checklist seed double-insert (`deals/[id]/checklist:83`), pipeline bootstrap dup.

**Chippi chat:** resume must re-verify `space.ownerId` ↔ caller (`task/resume:103-132`); possible duplicate `permission_required` SSE emission (`sdk-chat-stream:456-494`); `requiresApproval:'maybe'` could auto-run if `shouldApprove→false` on a real mutation (`sdk-bridge:62`); `strictifySchema` drops zod validators; `merge-persons` DealContact delete not space-scoped.

**Tours/Intake:** status page selects `applicationData`/`statusPortalToken` even without the portal token (verify the render path actually withholds them); all-time email dedup returns existing `id`+`applicationRef` to any caller (`public/apply:486`); brokerage dedup ref-fallthrough; `public/form-draft` trusts client `spaceId`; intake-chat rate-limit collapses to `'unknown'` key; deterministic scorer uses substring match on free-text fields.

**Autonomous:** run-lock release is non-atomic GET+DEL (`agent/security/budget.py:126`); `run_swarm` doesn't assert `payload.spaceId` matches the `SwarmRun` row; routine runs don't drain `run_now` signals; `agent/db.py` composite `on_conflict` quoting is a latent landmine.

**Brokerage:** `getBrokerContext` multi-membership tie-break is non-deterministic (add `.order('createdAt')`); seat-cap pending-count expiry-filter mismatch + no serialization (double-spend race); `broker/properties` OR predicate over-broad; review-comment `isRequester` path skips the offboarding gate; `computeCommission` `referral_in` can push `net > gci`.

**Client Portal:** OTP codes not invalidated on reissue (reset & verify — multiple live codes); portal GET has only per-IP rate-limit (no per-token); password reset marks email verified, bypassing the verify gate.

**Studio/Files:** storage-gc misses `files/` and `studio/` prefixes (unbounded Wasabi orphans); packet `expiresAt` null = permanent share; `documents/[id]` lookups lack defensive `spaceId`; studio spend cap is non-atomic read-check-write; `internal/*` shared-secret has no per-space binding.

**Billing/Admin:** `comp_free_month` writes `active` to DB and is silently reverted by the next unrelated Stripe webhook; telnyx-voice has no idempotency (duplicate Whisper/GPT spend on retries).

## Method note

This audit exists because the prose docs had already drifted from the code (the runtime default and the scoring model were both wrong in the docs). Findings here are pinned to `file:line` so they're checkable. Where an agent's claim didn't survive a direct read, it was downgraded — e.g. the intake "critical" was re-scoped once the query was confirmed to be `spaceId`-scoped and keyed on a 64-hex secret. Trust the line numbers, not the adjectives.
